# Qt Quick showcase — личная оценка на Windows

Это интерактивная демонстрация, на базе которой владелец оценил Qt Quick перед выбором архитектуры. Теперь PySide6 + Qt Quick выбраны как основа MVP согласно [ADR-0001](../../docs/architecture/decisions/ADR-0001-pyside6-qt-quick.md). Python-код, который увидел бы автор приложения, находится в [`example_app.py`](example_app.py). Реализация QML и Qt находится рядом, но не входит в пример.

## Что дважды щёлкнуть

**Основной путь:** `artifacts/qt_quick_showcase/START_SHOWCASE.cmd` от корня репозитория. Держите этот файл вместе со всей папкой `artifacts/qt_quick_showcase/QtQuickShowcase.dist/`. Запускается `QtQuickShowcase.dist/example_app.exe`. Не выбирайте отдельный EXE при копировании пакета: ему нужны соседние библиотеки, QML и медиа.

В окне есть восемь страниц: Controls & shapes, Themes, Animation, Dynamic & windows, Input, Media & devices, Performance, Diagnostics. Нажатия меняют строку состояния внизу; Diagnostics показывает версии, активный graphics backend и последние события. В `example_app.py` показаны `App`, `Theme`, `Window`, `Button`, `Star`, колбэки и `Pulse`, затем `app.run()`. Этот API демонстрационный и ограниченный: раскладка showcase пока задана внутри QML, а не строится произвольным деревом из примера.

**Резервный запуск из исходников:** `demos/qt_quick_showcase/START_SOURCE.cmd`. Он ищет 64-битный Python 3.13, затем 3.12 через Windows `py`; также принимает подходящий `python` в `PATH`. При первом запуске создаёт только `demos/qt_quick_showcase/.venv-showcase/`, ставит `PySide6==6.11.2` из [`requirements.txt`](requirements.txt), затем открывает приложение. Активация окружения и `.venv-qt-quick` не нужны. Глобальные Python-пакеты он не меняет. Для первой установки может понадобиться сеть; при её отсутствии сценарий выводит ошибку и предлагает повторить после восстановления соединения. Если Python не найден, установите 64-битный Python 3.13 с Windows launcher и повторите запуск.

Если пакет не открылся, сохраните текст консоли. Исходный launcher служит запасным путём. Если исходный launcher сообщает об ошибке установки, проверьте сеть и место на диске, затем запустите его снова. Для ошибки загрузки QML предусмотрен диалог с диагностикой, а для ошибки после создания окна — запись в Diagnostics; сами аварийные ветки отдельно не вызывались.

## Содержимое пакета и медиа

`QtQuickShowcase.dist/` содержит EXE, Python runtime, PySide6/Qt библиотеки и QML-модули, Qt Multimedia, QML-контролы и локальный синтетический `assets/sample.mp4`. На проверенной сборке это около **207 МБ** и примерно 2700 файлов. WAV-тон и тестовое изображение 2048 × 2048 создаются в Windows Temp при запуске; скачивание медиа не требуется. MP4 был сгенерирован в предыдущем эксперименте локальным FFmpeg из тестового изображения и тона; внешнего или лицензируемого стороннего контента нет. `theme.tokens` показывает несколько CSS-подобных токенов без парсера CSS.

## Что подтвердил Codex (Windows, 3 октября 2026)

- Среда: Windows 11 Pro build 26200, 64-bit; Python 3.13.9; PySide6/Qt 6.11.2; Intel Core i3-12100F (8 logical processors), 16 ГБ RAM, NVIDIA GeForce RTX 5060 Ti, driver 32.0.15.9636. В приложении зарегистрирован Direct3D11.
- `cmd /c demos\qt_quick_showcase\START_SOURCE.cmd --probe` завершился с кодом 0. Отдельная копия исходников вне репозитория через тот же launcher **создала новое выделенное окружение**, установила pinned PySide6 и также завершила smoke с `failures=[]`.
- Пакет создан официальным `pyside6-deploy` в режиме `standalone` (Nuitka 4.2.2). Папка пакета была скопирована в `%TEMP%\qt_quick_showcase_portable_test_0005\`, а `PATH` ограничен каталогами Windows; `PYTHONPATH`, `PYTHONHOME`, `VIRTUAL_ENV`, `QT_PLUGIN_PATH` и пути импорта QML удалены. EXE и `START_SHOWCASE.cmd --probe` завершили smoke с `failures=[]` без dev-venv и Qt SDK в путях. Это проверка **на одной Windows-машине**, не на другом ПК или чистой VM.
- Синтетические QtTest-клики вызвали три независимых Python callback. Клик в прозрачном углу звезды не активировал её. Синтетические Space и Enter активировали сфокусированные кнопку и звезду. Тёмная тема, остановка/повтор анимации, добавление/удаление control с отдельным ID и второе видимое окно прошли проверки. Снимки сохранены в [`captures/`](captures/), итоги исходного запуска в [`smoke-results.json`](captures/smoke-results.json), пакета — в [`portable-smoke-results.json`](captures/portable-smoke-results.json).
- Плееры перешли в PlayingState, а кадр MP4 виден на снимке. Перечислены четыре аудиовыхода, четыре аудиовхода и одна камера, обнаруженные на этой машине. Звук **не прослушивался физически**; запись с камеры/микрофона не запускалась. В финальных smoke-запусках ошибок QML и медиа не зарегистрировано.
- Сцены с 50 и 400 анимированными элементами и большим изображением загрузились. В последнем source-запуске 50 элементов: 112 интервалов `frameSwapped`, медиана 13.33 мс, p95 13.7 мс, процесс CPU около 6.2% одного логического ядра в одном секундном окне; 400 элементов: 136 интервалов, медиана 13.35 мс, p95 13.6 мс, CPU около 18.7%. Пакетный запуск из отдельной папки дал медианы около 13.3 мс для обоих уровней. Это краткие наблюдения конкретной машины и сцены; callbacks не измеряют FPS монитора и не доказывают видимую плавность.

Команды проверки, фактически выполненные из корня репозитория:

```powershell
cmd /c demos\qt_quick_showcase\START_SOURCE.cmd --probe
# Во внешней копии исходников: cmd /c START_SOURCE.cmd --probe
# Во внешней копии пакета, с очищенным Python/Qt окружением:
cmd /c START_SHOWCASE.cmd --probe --capture-dir C:\Users\zasim\AppData\Local\Temp\qt_quick_showcase_portable_test_0005\wrapper-captures
```

## Ограничения и проверка владельца

Первый вызов `pyside6-deploy` остановился на неинтерактивном запросе Nuitka о загрузке Dependency Walker. Повтор с `--assume-yes-for-downloads` собрал пакет. Автоматическое исключение `Qt6Test.dll` сначала ломало только встроенный smoke-режим пакета; финальная папка содержит эту библиотеку и прошла smoke-проверку. `dumpbin` в PATH не был доступен, поэтому автоматическая проверка зависимостей Qt при сборке была пропущена. Фактический запуск из внешней папки проверен отдельно.

Владелец должен лично проверить:

1. Мышью: hover, press и точность попадания у краёв звезды; клавиатурой: Tab-порядок, фокусная рамка, Space/Enter.
2. Слышен ли локальный тон и звук MP4 на выбранном аудиовыходе.
3. Насколько приятно выглядят светлая/тёмная темы, размеры, текст и движение на его дисплее; есть ли заметные рывки при 50/400 элементах.
4. Если есть оборудование: touch, актуальность списков камер/микрофонов и разрешения ОС. Захват камерой и микрофоном здесь не реализован.
5. Если нужен перенос на другой ПК: запускается ли полная папка пакета там без установленного Python/Qt; другие GPU, DPI, кодеки и версии Windows не проверены.

Владелец запустил демонстрацию и оценил её положительно. Он отметил несоответствие контраста нижней строки в Follow System при системной тёмной теме и необычное движение точек; детали и объяснение по коду записаны в [TASK-0005](../../tasks/done/TASK-0005-interactive-qt-quick-showcase.md). Физический touch, доступность со screen reader, DPI-вариации и другие платформы остаются непроверенными.

Официальная справка по инструменту сборки: [Qt for Python `pyside6-deploy`](https://doc.qt.io/qtforpython-6/deployment/deployment-pyside6-deploy.html).
